# Sicherheitsrichtlinie – VIC-GDI

**Status:** Konzept- und Dokumentationsrepository; derzeit keine produktiv freigegebene GDI-Softwaredistribution.

## Sicherheitsprobleme vertraulich melden

Bitte **keine** Sicherheitslücken, Zugangsdaten, Tokens, vertraulichen Server-/Netzwerkdetails oder personenbezogenen Daten in öffentlichen Issues, Pull Requests oder Diskussionen veröffentlichen.

- **Bevorzugt:** GitHubs Funktion **Private vulnerability reporting**, sofern für dieses Repository aktiviert (Bereich **Security and quality → Advisories → Report a vulnerability**).
- **Falls nicht verfügbar:** Den Repository-Eigentümer über einen bereits etablierten **privaten** Kommunikationsweg kontaktieren. Bis ein vertraulicher Meldeweg vereinbart ist, **keine Details öffentlich posten**.
- Für bereits veröffentlichte Zugangsdaten gilt: betroffene Geheimnisse unverzüglich widerrufen/rotieren und den möglichen Zugriff untersuchen. Das Löschen einer Datei oder eines Commits allein genügt nicht.

## Geltungsbereich

Dieses Repository enthält derzeit das GDI-Konzept und technische Entscheidungsgrundlagen, **keinen produktiven Servercode und keine unterstützten Software-Releases**. Deshalb gibt es derzeit keine Liste unterstützter Softwareversionen.

Sicherheitslücken in QGIS, PostgreSQL/PostGIS, Proxmox oder anderen Drittprodukten sollten zusätzlich entsprechend den Sicherheitsrichtlinien der jeweiligen Upstream-Projekte gemeldet werden. Diese Richtlinie ist **keine Aussage**, dass eine bestimmte Zielarchitektur schon sicherheitsgeprüft oder produktiv freigegeben wäre.

## Umgang mit Beiträgen

Öffentliche Beiträge dürfen nur zur Veröffentlichung freigegebene Informationen enthalten. Insbesondere keine Zugangsdaten, internen IP-/Hostnamen, produktiven Daten oder sensiblen Konfigurationsdateien veröffentlichen.
